# Omarchy marketplace security-review closure

This document maps every blocking point from HANCORE-linux's manual review of marketplace issue [#4074](https://github.com/omacom/omarchy-plugin-marketplace/issues/4074) to a concrete boundary and regression test. Revalidation must bind to the final commit containing all controls below.

| Review requirement | Implemented boundary | Regression evidence |
|:--|:--|:--|
| Do not persist cross-tool behavioral instructions during marketplace install | `scripts/install.sh` neither copies nor removes `skill/`. `install-agent-skill` is a separate, explicit action with a fixed target; its removal is separate too. | `MetadataTests.test_agent_skill_is_separate_explicit_opt_in`; install lifecycle asserts the skill is absent until opt-in. |
| Contain skill destination and refuse ownership/collision/symlink/unmanaged-content problems | `managed-tree.py` confines the fixed target below the user's home, checks each existing component with `lstat`, requires current-user ownership, refuses links/special files, records every file/directory/mode/size/hash, stages atomically, and verifies the old tree before update/removal. Production path overrides are refused. | Install lifecycle covers clean opt-in, modified-content refusal, exact removal, and unmarked collision refusal. |
| Bound executable downloads and enforce redirect/final origin | Each artifact lock includes exact compressed size and redirect host allowlist. `safe-download.py` allows HTTPS/443 only, manually validates every redirect (maximum three), rejects implicit redirects, checks `Content-Length`, free disk, streamed bytes, exact final size, and SHA-256, and uses an exclusive `O_NOFOLLOW` temporary file. | `SafeDownloadTests` covers URL policy, accepted/rejected redirects, declared-size mismatch, stream overflow, and digest failure. |
| Reject dangerous/unexpected archives before extraction | `safe-extract.py` fully enumerates an archive before writes; rejects absolute/traversal/backslash paths, duplicates, symlinks/hardlinks, special files, encrypted entries, unexpected roots, and locked count/per-file/total expansion limits. It then extracts regular files manually with `O_EXCL|O_NOFOLLOW`. | `SafeExtractTests` builds malicious traversal/link/hardlink/FIFO/unexpected/duplicate/oversized archives and proves fail-closed behavior. |
| Never follow extracted links for chmod/install | Upstream link-bearing packages are reproducibly converted into ordinary-file-only release assets. Required platform links are declared separately and created only after extraction; binary checks use `lstat`, and archive links are always rejected. | Lock verification requires extraction policies; safe-extract tests reject archive links and verify exact post-extraction tree/link manifests. |
| Disclose and own all out-of-plugin state | README lists every path/change and uninstall behavior. Application, config, state, cache, copied-plugin, optional skill, and systemd units carry scope-specific ownership markers; unmarked collisions and symlink components fail closed. | Install/uninstall lifecycle and metadata tests cover markers, foreign collisions, bounded menu state, and unit headers. |
| Collision-safe staging, transactional rollback, complete uninstall | The full replacement app/toolchain/state/unit set is built under a private transaction directory. Commit keeps backups and restores app/state/units/link/menu/config/plugin-copy/shell-state on error. Update requires an unlocked session and snapshots the native checkout plus `shell.json` before Omarchy fast-forwards it. Uninstall preflights first, snapshots the native checkout plus shell state before the official destructive removal, moves its exact owned set transactionally, preserves config/cache by default, purges only marked roots, and does not touch the optional skill. | Failure injection after the application commit proves the old application, CLI link, and state survive. Metadata tests require checkout/shell-state rollback code. Clean install/update/uninstall/purge remain in the acceptance matrix. |

## Reviewer-positive foundations retained

Pinned versions and hashes, the fully hashed Python lock, pinned CI actions, attestations, loopback-only services, and account-free/offline defaults remain intact. Manual setup is explicit in the README and marketplace submission.
